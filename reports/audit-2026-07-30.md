### C-2: toast.js 中 XSS 风险 — innerHTML 注入未转义内容

**文件**: `js/components/toast.js`  
**行号**: 57-62, 134-148, 192-207, 258-268  
**问题描述**: `toast._show()` 和 `showConfirm()` / `showInput()` / `showForm()` 等方法中，大量使用 `innerHTML` 模板字符串直接插入未转义的用户输入：

```javascript
// toast.js:58 — message 直接插入 innerHTML，若含 <script> 则 XSS
el.innerHTML = `
  <span class="siper-notif-icon">${icons[type] || 'ℹ'}</span>
  <span class="siper-notif-msg">${message}</span>  // ← 未转义
  ...
`;
```

`showConfirm()` 中的 `title`、`msg`、`scope`、`impact` 均直接插入 innerHTML，未调用 `escapeHtml()`。

**修复建议**: 
- 对所有插入 innerHTML 的用户可控内容使用 `escapeHtml()` 转义
- 或改用 `textContent` + `createElement` 构建 DOM

### C-3: API Key 可能泄露到前端日志/网络请求

**文件**: `js/pages/model-settings.js:389`  
**问题描述**: `saveModelsImmediate()` 中将 `api_key` 通过 HTTP POST 发送到后端。虽然代码做了脱敏检查（`m.api_key.startsWith('*')`），但明文的 `api_key` 会出现在：
1. 浏览器 Network 面板
2. `window.settingsModelsCache` 中可被 console 访问
3. `loadSettingsModels()` 返回的数据中

**修复建议**: 
- 全局设置页的模型列表不应返回 `api_key`，应仅返回脱敏后的 `***...`
- 新增模型时通过单独的安全端点提交

### H-10: CSS `max-max-width` 拼写错误

**文件**: `css/style.css`  
**行号**: 399, 1506, 1509  
**问题描述**: 
```css
.prompt-modal { width: 90%; max-max-width: 640px; max-height: 80vh; }
@media (max-max-width: 900px) { ... }
@media (max-max-width: 768px) { ... }
```
`max-max-width` 是无效的 CSS 属性（应为 `max-width`）。第399行和第1506/1509行的 `@media (max-max-width: ...)` 也是无效的（应为 `@media (max-width: ...)`）。

这意味着 `.prompt-modal` 的宽度限制和两个响应式断点完全无效。

**修复建议**: 全局替换 `max-max-width` → `max-width`。
