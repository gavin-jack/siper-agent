# Markdown 渲染修复 — 列表项连在一起 & 表格后换行（v0.9.55）

## 问题描述

LLM 输出的 Markdown 格式不规范时，渲染器出现两个问题：
1. **连在一起的列表项无法切分**：如 `-凌晨~早晨：多云- 上午：多云转晴- 下午：局部多云` 被当作一个段落
2. **表格后没有视觉分隔**：表格和后续内容之间没有空行

## 根因分析

### 问题1：列表项连在一起

预处理中的 `ulRe` 正则 `/(?<=^|\s)(?=-[^\s-])/g` 无法匹配 `-` 前面是中文字符的情况（如 `较高-上午`）。

主循环中的无序列表检测 `/^[-*+]\s/` 要求 `-` 后有空格，无法匹配 `-凌晨` 这种无空格格式。

### 问题2：表格后无换行

表格渲染完后 `i = j; continue;` 直接跳到下一行，没有插入视觉分隔。

## 修复方案

### 1. 预处理 ulRe 改进

用两个正则组合：
- `/(?<=\S)(?=- )/g` — 匹配 `- `（横杠+空格）前面是非空白字符的位置（处理 `较高- 上午`）
- `/(?<=\S)(?=-[^\s-])/g` — 匹配 `-` 前面是非空白字符且 `-` 后面是非空白非 `-` 的位置（处理 `较高-上午` 无空格）

**注意**：原正则 `/(?<=^|\s)(?=-[^\s-])/g` 无法匹配 `-` 前面是中文字符的情况（如 `较高-上午`），因为中文字符不是 `\s`。也不能用 `/(?<=[\u4e00-\u9fff])(?=-[^\s-])/g` 因为 Unicode 范围不全。最终方案是用 `(?<=\S)`（前面是非空白）来覆盖所有情况。

**陷阱**：`(?<=\S)(?=-[^\s-])` 不会匹配 `- 上午`（- 后面有空格），因为 `[^\s-]` 排除了空格。所以需要第一个正则 `(?<=\S)(?=- )` 来处理 `- ` 有空格的情况。两个正则互补。

### 2. 主循环无序列表检测

从 `/^[-*+]\s/` 改为 `/^[-*+]/`，支持 `-无空格` 格式。
移除条件改为 `/^[-*+] ?/`（可选空格）。
加 `line.trim().length > 1` 防止单字符 `-` 被误判。

### 3. 表格后换行

表格渲染完后插入 4px 高的空 div：
```javascript
const _tblBr = document.createElement('div');
_tblBr.className = 'md-table-after-br';
_tblBr.style.height = '4px';
frag.appendChild(_tblBr);
```

## 版本号缓存绕过

修改 core.js 后必须在 index.html 中更新 `?v=` 版本号（如 `?v=20260522a`），否则 browser tool 和用户浏览器都可能加载旧版 JS。

## 验证方法

在浏览器控制台测试：
```javascript
const text = '## 标题\n| A | B |\n|---|---|\n| 1 | 2 |\n\n**加粗：**\n-项1- 项2- 项3\n\n段落';
const frag = renderMarkdown(text);
const div = document.createElement('div');
div.appendChild(frag);
console.log(div.innerHTML);
```

期望结果：
- 表格正确渲染
- 表格后有 4px 空行 div
- 列表项被正确切分为 3 个 `<li>`
