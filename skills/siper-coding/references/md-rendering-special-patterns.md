# MD 渲染特殊模式分析（v0.9.68+）

## 问题：LLM 输出非标准 MD 导致渲染异常

### 模式 1: `---###🏮 解梦`（HR + 标题同行）

**症状**: 用户看到原始文本 `---###🏮 解梦...` 而不是渲染后的 HR + H3

**分析**:
- 预处理阶段（core.js 2540-2610 行）的 heading 分割正则 `/(?:^|[^#])(#{1,6})\s*[^#]/g` 能正确分割 `---` 和 `###...`
- `---` 被识别为 HR，`###🏮 解梦` 被识别为 H3
- **预处理逻辑正确**，分割本身没问题

**可能原因**:
1. 浏览器缓存旧版 core.js（需硬刷新 Ctrl+Shift+R）
2. LLM 输出中包含不可见字符（如零宽空格、BOM）干扰正则匹配
3. 预处理 skip 条件（`l.length < 5 || (!l.includes('#') && ...)`）过滤掉了该行

**诊断步骤**:
1. 硬刷新浏览器
2. 在 browser_console 中检查原始消息文本: `document.querySelectorAll('.msg-body')[-1].textContent`
3. 检查是否包含不可见字符

### 模式 2: `**bold****1. list**`（bold + 列表标记粘连）

**症状**: `**加粗文本****1. 列表项**` 中的 bold 标记被破坏

**分析**:
- 预处理阶段会按 `**` 分割行，当 `**` 出现在行中间且紧跟列表标记时：
  - `**bold****1. list**` 被分割为 `["**bold**", "**1. list**"]`
  - 第一部分 `**bold**` 正确渲染为 bold
  - 第二部分 `**1. list**` 中的 `**` 被当作 bold 标记，但 `1. list` 中的数字列表标记被 bold 包裹
- **根本原因**: LLM 输出不规范，`**` 和 `1.` 之间没有换行

**这不是 renderMarkdown 的 bug**，而是 LLM 输出格式问题。

### 预处理 skip 条件（core.js:2547）

```javascript
l.length < 5 || (!l.includes('#') && !l.includes('|') && !/\d+\./.test(l) && !/^[-*+]/.test(l))
```

满足以下条件时，行**不做预处理分割**：
- 长度 < 5
- 不含 `#`、`|`、数字列表标记、无序列表标记

### 主循环检查顺序（core.js:2620-2920）

```
fenced code → table → headings → HR → blockquote → ul → ol → empty → paragraph
```

**关键**: heading 检测在 HR 和 blockquote 之前，所以 `# ` 开头的行不会被误判为列表。

## 诊断 MD 渲染问题的标准流程

1. **硬刷新浏览器**（Ctrl+Shift+R）排除缓存
2. **检查原始文本**: browser_console 中读取 `.msg-body` 的 textContent
3. **检查不可见字符**: 用 `charCodeAt()` 检查每个字符
4. **模拟预处理**: 在 browser_console 中手动执行预处理正则，观察分割结果
5. **确认不是 LLM 输出问题**: 如果原始文本本身格式不规范，是 LLM 问题不是渲染问题
