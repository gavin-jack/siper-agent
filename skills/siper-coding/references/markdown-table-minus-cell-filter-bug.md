# 表格数据单元格中单个"-"被误过滤为分隔符

## 问题

表格数据单元格中的 `-`（表示"无"或"不适用"）被 `_splitTableRowSegments` 中的 `realCells` 过滤条件误判为分隔符单元格并过滤掉。

典型输入：
```
|文件名 | 类型| 大小 |修改日期|
|--------|------|------|----------|
| `程序` | 文件夹| - |5月22日 |
| `hermes-memory-backup` | 文件夹| - |5月7日|
```

渲染结果：每行只有 3 个单元格（文件名、类型、修改日期），`-` 丢失。

## 根因

`_splitTableRowSegments` 中的过滤条件：
```javascript
const realCells = cells.filter(c => !/^[\s\-:]+$/.test(c));
```

正则 `/^[\s\-:]+$/` 匹配"只包含空白、`-`、`:` 的字符串"。单个 `-` 完全匹配此正则，被当作分隔符单元格过滤掉。

## 修复

将过滤条件改为只过滤包含 3+ 连续 `-` 的单元格（分隔符模式）：

```javascript
// ✅ 正确：只过滤 --- 或更长，保留单个 -
const realCells = cells.filter(c => !/^[\s:]*---[\s:]*$/.test(c));

// ❌ 旧代码：单个 - 也被过滤
const realCells = cells.filter(c => !/^[\s\-:]+$/.test(c));
```

## 边界情况

| 单元格内容 | 旧代码 | 新代码 | 说明 |
|-----------|--------|--------|------|
| `-` | ❌ 过滤 | ✅ 保留 | 单个连字符是合法数据 |
| `--` | ❌ 过滤 | ✅ 保留 | 双连字符也是合法数据 |
| `---` | ❌ 过滤 | ❌ 过滤 | 三连字符是分隔符，正确过滤 |
| `----` | ❌ 过滤 | ❌ 过滤 | 四连字符也是分隔符 |
| `- -` | ❌ 过滤 | ✅ 保留 | 带空格不是分隔符模式 |
| `:` | ❌ 过滤 | ✅ 保留 | 冒号不是分隔符 |
